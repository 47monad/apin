# Migrating to v0.2.0

v0.2.0 is a breaking release. It standardizes readiness checks, makes RabbitMQ
channels caller-owned, represents etcd endpoints as a list, removes the `closr`
package, and splits Prometheus gRPC instrumentation into its own module. It also
adds `redisinitr` and hardens the HTTP server. This guide covers each change and
the release checklist.

## Breaking changes

### 1. `config`: explicit empty environment values, slices, and env-only loading

`config.Load` keeps its signature `Load(configPath, envPath, destination)`.

- An empty `configPath` skips file decoding, so a destination can be built from
  the environment alone.
- `[]string` fields decode from trimmed comma-separated environment values.
- A present-but-empty environment value is now a value, not an absence. It
  overrides lower-precedence sources: strings and `[]string` fields become
  empty, and scalar fields fail conversion with field and variable context.

**Migration:** if you set a process or `.env` variable to an empty value to mean
"unset", actually unset it so the `.env`/config-file value can apply.

```go
// env-only configuration
var cfg serviceConfig
if err := config.Load("", ".env", &cfg); err != nil {
	return err
}
```

### 2. `etcdinitr`: `Config.Endpoints` is `[]string`

`Config.Endpoints` changed from a comma-separated `string` to a `[]string`.
Configuration files must use a list, and code must pass a slice. Environment
values remain comma-separated and are split by the config loader. An empty list
or a blank entry is rejected by `New`.

```go
// before
etcdinitr.WithConfig(&etcdinitr.Config{Endpoints: "a:2379,b:2379"})
// after
etcdinitr.WithConfig(&etcdinitr.Config{Endpoints: []string{"a:2379", "b:2379"}})
```

```yaml
etcd:
  endpoints:
    - "a:2379"
    - "b:2379"
```

### 3. `rmqinitr`: caller-owned channels

`Shell.GetChannel` is replaced by `Shell.NewChannel`, which opens a new channel
on the current connection and returns it to the caller. The caller owns and
closes that channel. Closing a caller channel no longer marks the shell
unhealthy or triggers a reconnect; only connection loss does. After a reconnect,
open a new channel.

```go
ch, err := shell.NewChannel()
if err != nil {
	return err
}
defer ch.Close()
```

`WaitForHealth` and `Ready` are unchanged. `Ready` reports the current state;
`WaitForHealth` waits for recovery.

### 4. `prominitr`: gRPC instrumentation moved to `promgrpcinitr`

`prominitr` is now limited to the Prometheus registry. `Shell.GRPCServerInterceptor`,
`Shell.GRPCServerMetrics`, `Config.GRPCMetrics`, and `WithGRPCMetrics` are
removed, and the module no longer depends on gRPC or OpenTelemetry.

Use the new `promgrpcinitr` module, which accepts a `prometheus.Registerer` and
exposes unary and stream interceptors plus native server metrics:

```go
promShell, err := prominitr.New(ctx, prominitr.WithProcessCollector(true))
if err != nil {
	return err
}

rpcMetrics, err := promgrpcinitr.New(ctx, promgrpcinitr.WithRegisterer(promShell.Registry))
if err != nil {
	return err
}

grpcShell, err := grpcinitr.NewServer(ctx, cfg.GRPC.Servers["api"],
	grpcinitr.WithInterceptor(rpcMetrics.UnaryInterceptor),
	grpcinitr.WithStreamInterceptor(rpcMetrics.StreamInterceptor),
)
if err != nil {
	return err
}
```

`prominitr` also gains optional Go and process collectors through
`Config.GoCollector` / `Config.ProcessCollector` or `WithGoCollector` /
`WithProcessCollector`.

### 5. `closr` removed

The `github.com/47monad/apin/closr` compatibility package is removed. Use
`apin.Closer`, `shell.Close(ctx)`, or `apin.App` directly:

```go
if err := shell.Close(ctx); err != nil {
	return err
}
```

## New in v0.2.0

### Readiness contract

`apin.ReadinessChecker` defines `Ready(context.Context) error`, implemented by
the PostgreSQL, MongoDB, etcd, and RabbitMQ shells. PostgreSQL keeps `Ping` as
an alias. Bound the probe with a deadline-bearing context:

```go
readyCtx, cancel := context.WithTimeout(ctx, 5*time.Second)
defer cancel()
if err := shell.Ready(readyCtx); err != nil {
	return err
}
```

### `redisinitr`

A new independently installable Redis module using
`github.com/redis/go-redis/v9`. The shell exposes a `redis.UniversalClient`
covering standalone, Sentinel, and cluster deployments.

```go
type serviceConfig struct {
	Redis *redisinitr.Config `json:"redis" yaml:"redis"`
}

redisShell, err := redisinitr.New(ctx, redisinitr.WithConfig(cfg.Redis))
if err != nil {
	return err
}
if err := redisShell.Ready(readyCtx); err != nil {
	return err
}
```

`Config` holds addresses, username, password, database, and master name.
Construction is lazy; `Ready(ctx)` pings and `Close(ctx)` releases the client.

### HTTP server hardening

`ServerConfig` and `httpinitr` options now cover host, read-header/read/write/
idle timeouts, and a max header size limit, plus `WithBaseContext` and
`WithNativeServer` escape hatches. Defaults are an empty host, 10s read-header,
zero read/write (streaming-compatible), 120s idle, and
`http.DefaultMaxHeaderBytes`.

```go
readHeader, idle := 10, 120
shell, err := httpinitr.NewServer(ctx, httpinitr.ServerConfig{
	Host:              "127.0.0.1",
	Port:              8080,
	ReadHeaderTimeout: &readHeader,
	IdleTimeout:       &idle,
	MaxHeaderBytes:    1 << 16,
},
	httpinitr.WithBaseContext(baseContext),
	httpinitr.WithNativeServer(func(server *http.Server) error {
		server.ErrorLog = errorLogger
		return nil
	}),
)
```

`Listen` followed by `Serve` now tracks the listener once.

### gRPC stream interceptors and metrics

`grpcinitr.WithStreamInterceptor` appends a stream interceptor, matching the
existing unary `WithInterceptor`. Combined with `promgrpcinitr` it records both
unary and server-streaming metrics (see the migration example above).

## Release checklist

Before tagging v0.2.0:

- `scripts/release.sh --check` — builds, vets, and tests every module without
  workspace substitution, then runs the temporary consumer isolation checks.
- `scripts/lint.sh` — pinned golangci-lint across every module.
- Race tests where concurrency is involved, e.g. `go test -race ./...` in
  `initrs/rmqinitr` and `initrs/httpinitr`.
- Isolated consumer checks confirm `prominitr` pulls no gRPC/OpenTelemetry and
  `redisinitr` pulls no other initrs.
- Green CI on `main`.

Then create the local tags for every release module:

```bash
scripts/release.sh v0.2.0
```

This validates the whole tree and creates `v0.2.0` plus `initrs/<module>/v0.2.0`
tags locally. Publishing the tags is a separate, explicit step.
